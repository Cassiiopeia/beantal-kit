# 점검과 비판 기준

비판은 **칭찬으로 시작하지 않고, 근거(슬라이드 번호 · 요건 ID · 수치)가 있는 판단만** 한다.
자동 점검(`review`)이 사실을 모으고, Claude 가 6축으로 판단한다.

## 1. 자동 점검 코드

| 코드 | 무엇 | 등급 |
|---|---|---|
| Q01 | 요건 커버리지 — 작성요청·업무범위·SLA·평가 요건 중 덱에서 다룬 흔적이 약한 것 | 🟥 |
| Q02 | 작성자 메모 잔존 (라벨 `수정`, "넣기", "확인 후 기재", 구어체, 노트 영역 메모) / 빨간 글씨 확인 | 🟥 / 🟩 |
| Q03 | 회사 수치 불일치 — 같은 지표의 서로 다른 값, 회사 프로필 확정값과 다른 값 | 🟥 |
| Q04 | 다른 고객사명 등장 (재사용 장표 잔존 가능성) | 🟨 |
| Q05 | `[확인 필요]` · `XX` · `OOO` 같은 빈칸 | 🟥 |
| Q06 | 목차 ↔ 상단 번호 · 섹션명 불일치, 목차 번호 건너뜀 (원인 단위로 묶어 보고) | 🟨 |
| Q07 | 헤더 규격 · 슬라이드 크기 이탈 | 🟨 |
| Q08 | 하우스 글꼴 외 글꼴, 슬라이드 마스터 2개 이상 | 🟨 |
| Q09 | 말투 — 메시지 길이·어미, 반말 종결, 영문 `or` | 🟨 / 🟩 |
| Q10 | 오타 사전 | 🟨 |
| Q11 | 기호 (`ㆍ`) | 🟩 |
| Q12 | 파일 크기 (메일 첨부 한도) | 🟩 |
| Q13 | 근거 없는 최상급 | 🟨 |

판정 힌트: 🟥 1건 이상 "제출 불가", 🟨 6건 이상 "보완 후 제출", 그 외 "형식상 제출 가능".
**오탐이 의심되면 숨기지 말고 "오탐 가능"으로 표시해 보고한다.** 반복되는 오탐은 skill 개선 대상이다.

## 2. 6축 채점 (Claude)

각 축 1~5점, 점수마다 근거를 단다.

| 축 | 질문 | 근거로 쓰는 것 |
|---|---|---|
| 1 RFP 적합성 | 작성 요청 항목을 빠짐없이, 같은 순서로 다루는가 | 커버리지, 목차 vs RFP 8장류 |
| 2 논리 구조 | 결론 → 근거 → 실행 흐름인가, 중복·비약은 없는가 | 섹션 흐름, 슬라이드 순서 |
| 3 메시지 | 장마다 결론형 메시지가 있고 본문이 뒷받침하는가 | stats.message_ratio, 메시지 원문 |
| 4 근거·수치 | 주장마다 숫자·실적·증빙이 있고 서로 일치하는가 | Q03, stats.numbers_in_messages |
| 5 차별성 | 경쟁사 이름으로 바꿔 끼워도 말이 되는 일반론이 아닌가 | 메시지·제안 방향 원문 |
| 6 완성도·형식 | 메모·빈칸·번호·글꼴·오타 | Q02·Q05·Q06·Q08·Q10 |

판정: 평균 4.0 이상 "제출 가능", 3.0~3.9 "보완 후 제출", 3.0 미만 "재구성 권고". 축 6 에 🟥 가 있으면 평균과 무관하게 "제출 불가".

## 3. 보고 형식

1. 판정 한 줄 + 6축 점수표
2. 반드시 고칠 것 (🟥) — 슬라이드 · 무엇 · 고치는 법
3. 고치면 좋은 것 (🟨) — 원인 단위로 묶어서
4. 구조 제안 — 빠진 장표, 순서 변경, 합칠 장표 (근거 요건 ID 와 함께)
5. 사용자가 정해야 할 것 — `[확인 필요]` 목록
