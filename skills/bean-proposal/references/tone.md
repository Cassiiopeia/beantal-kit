# 말투 규칙

제안서 문장은 **2층 구조**다. 슬라이드 상단의 거버닝 메시지(결론)는 존댓말 서술형, 본문은 개조식 명사형.
(근거: 사내 우수 제안서 실측 — 메시지 평균 51~58자, 본문 한 줄 평균 23~28자, 본문의 60% 이상이 명사형 종결)

## 1. 거버닝 메시지 (슬라이드당 1개)

| 규칙 | 기준 | 이유 |
|---|---|---|
| 결론 먼저 | 이 장에서 평가자가 기억할 한 문장 | 평가자는 메시지만 훑어 읽는다 |
| 길이 | 25~110자, 최대 2줄 (14pt · 폭 25cm 기준 한 줄 약 55자) | 3줄이면 결론이 흐려진다 |
| 어미 | 현황·사실 `~입니다/~합니다`, 약속·제안 `~하겠습니다`, 실적 `~하였습니다`, 안 제시 `~제안드립니다` | 같은 덱 안에서 어조가 흔들리면 신뢰가 떨어진다 |
| 숫자 | 가능하면 구체 숫자 1개 이상 (물량, 기간, 비율, 건수) | "다수의", "많은"은 근거가 아니다 |
| 금지 | 명사형 제목 반복("물량 분석"), 근거 없는 최상급("업계 최고", "유일한") | |

좋은 예: "8~9월 2개월에 연간 택배 물량의 50%가 집중되어, 연중 상시 대응이 가능한 운영 구조가 필요합니다."

## 2. 본문 불릿

| 규칙 | 기준 |
|---|---|
| 종결 | 명사형 (`~수립`, `~관리`, `~운영`), 마침표 없음 |
| 길이 | 한 줄 15~30자, 최대 45자 |
| 반말 금지 | `~한다`, `~필요하다`, `~해야 함` 은 작성 메모로 오인된다 |

좋은 예: "물량 Forecast 기반 사전 인력 · 공간 계획 수립"

## 3. 기호

| 용도 | 기호 | 예 |
|---|---|---|
| 나열 | ` · ` (앞뒤 공백) | 분실 · 파손 · 오배송 |
| 흐름 | `→` | 수령 → 저장 → 파기 |
| 양방향 | `↔` | 플랫폼 ↔ 풀필먼트사 |
| 소제목 | `【 … 】` | 【 우리 대응 역량 】 |
| 축·단계 | `① ② ③` | ① 단일 창구 |
| 하위 항목 | `-` | |

`ㆍ`(한글 아래아)는 쓰지 않는다.

## 4. 용어

- 업계 용어는 영문 그대로: CAPA, SLA, Cut-off, API, PLT, WH, Peak, Forecast, Sandbox.
- 영문 문장은 표지 슬로건에만. 본문에 `or`, `and` 대신 `또는`, `/`.
- 고객사는 첫 등장 때 정식 명칭, 이후 고객사가 스스로 쓰는 약칭. 우리 회사는 회사명 하나로 통일 (당사·저희 혼용 금지).

## 5. 절대 남기면 안 되는 것

작성자 메모(`수정`, `넣기`, `확인 후 기재`, `이래서`, `~해야 함`), 반말 메모, 다른 고객사명이 남은 재사용 장표, `[확인 필요]` 빈칸.
자동 점검(`review`)이 잡지만, 쓰는 단계에서 만들지 않는 것이 먼저다.

## 6. POINT 막대 (장 하단 한 줄 요약)

평가자(화주사)는 POINT 에서 **"그래서 우리에게 무엇이 좋아지나"** 를 읽는다. 우리가 어떻게 일하는지는 본문이 이미 보여 준다.

| 규칙 | 내용 |
|---|---|
| 결과만 | 줄어드는 것 · 빨라지는 것 · 막아지는 것 · 유지되는 것을 쓴다 |
| 과정 금지 | 우리 작업 동작(담고, 붙이고, 스캔해, 적치, 피킹하고 …)은 쓰지 않는다. 화주사에게는 당연한 일이다 |
| 화살표 금지 | `A → B` 로 쓰지 않는다. 화살표 앞은 거의 과정 설명이 된다 → B(결과)만 남긴다 |
| 길이 | 한 줄, 55자 이하 |
| 숫자 | 결과를 보여 주는 숫자는 좋다 (오출고 0건 목표, 보충 횟수 절반) |

| ✗ 과정 | ✓ 결과 |
|---|---|
| 렌즈는 SKU별 빈에 담고 빈마다 바코드를 붙입니다 | 도수 · 컬러가 비슷한 렌즈도 오출고 없이 출고합니다 |
| 해외 특송을 전량 징동으로 일원화합니다 → 운임 조건은 별첨 견적서로 제시 | 해외 출고 창구가 하나로 줄어 인계 누락이 없습니다 |
| 많이 팔리는 65 SKU는 PLT · 박스에서 바로 피킹하고 … | 주력 SKU 보충 대기 없이 당일 출고를 지킵니다 |
