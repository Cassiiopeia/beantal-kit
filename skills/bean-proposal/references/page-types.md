# 페이지 유형과 outline.md 문법

## 1. 덱 뼈대

```
표지(T01) → 목차(T02) → [간지(T03) → 본문 n장] × 섹션 → 회사 소개(L01~L06) → (별첨) → 마무리(T04)
```

- **섹션 순서 = RFP 의 "제안서 작성 요청 사항" 순서.** 평가자가 요구 항목을 찾기 쉽게 하는 정석이다.
- 01 섹션은 항상 개요(Summary): 제안 방향(C01) → 요건 대응 총괄(C02, 대형 RFP) → 현황 분석(C05).
- RFP 가 "운영조직", "SLA", "전환 계획"을 요구하면 각각 한 장 이상 둔다 (자주 빠진다).

## 2. 공통 헤더 (본문 슬라이드)

섹션명(작게, 회색) · 섹션 번호 `01.` · 슬라이드 제목 · (고객사 표시) · 거버닝 메시지 · 구분선.
위치·글꼴·색은 config 의 `header` 값을 쓴다. 기존 제안서가 있으면 `profile` 로 실측해 채운다.
**섹션 번호와 섹션명은 목차와 반드시 같아야 한다** (자동 점검 Q06).

## 3. 유형 카탈로그

| 코드 | 유형 | 언제 | outline 필드 |
|---|---|---|---|
| T01 | 표지 | 덱 첫 장 | 메시지(부제: 핵심 약속 한 줄) |
| T02 | 목차 | 둘째 장 | (섹션에서 자동 생성) |
| T03 | 간지 | 섹션 시작 | 섹션 |
| T04 | 마무리 | 마지막 | 제목(기본 "감사합니다."), 메시지 |
| C01 | 제안 방향 | 01 섹션 첫 장 | 본문: 【RFP 핵심 과제】 【우리 대응 역량】 【제안 방향 3대 축】 세 그룹 → 2단 + 하단 3축 배치 |
| C02 | 요건 대응 총괄 | 요건 20개 이상 | 표: 분류 / 항목 수 / 즉시 / 협의 / 확인 |
| C03 | 요건 대응표 | 요건별로 정확히 대조해야 할 때 (3-1절을 먼저 본다) | 표: 요구 사항 / 우리 대응 / 근거·증빙 (한 장 최대 7행) |
| C04 | 프로세스 | 단계 흐름 | 단계: `이름 \| 설명1; 설명2` (최대 6단계) |
| C05 | 현황 분석(차트) | 물량·추이 | 데이터: 첫 열 = 항목, 나머지 열 = 계열 (숫자) |
| C06 | 거점·센터 | 운영 거점 | `사진:`(레퍼런스 센터 사진 `ref:<id>/<키>`) + 표 또는 본문 |
| C07 | 비교안 | 1안/2안 | 본문: 【1안 …】 【2안 …】 두 그룹 → 2단 카드 |
| C08 | 일정 | 전환·오픈 일정 | 표: 단계 / 기간 / 산출물 |
| C09 | 사례·실적 | 유사 운영 실적 | 데이터: 지표 / 전 / 후 → 막대 차트 (단위가 같은 지표만 한 차트에). 단위가 섞이면 표: 지표 / 전 / 후 (고객명은 익명 가능) |
| C10 | 보안·증빙 | 개인정보 | 단계(생애주기) 또는 표(요구 / 운영 방식 / 증빙) |
| C11 | 정산·단가 | 비용 구조 | 표: 카테고리 / 청구 항목 / 구분 제공 |
| C12 | 타임테이블 | 추진 일정·전환 계획 (Milestone) | `기간:` 열(예 `10월 4W, 11월 1W`) + `일정:` 표(항목 / 세부 일정 / 시작 / 끝 / 표시). 월·주 2단 머리, 같은 항목은 세로 병합, 기간 칸 위 화살표 막대(짙은·옅은 번갈아) 끝에 표시(기본 "완료", `-`면 없음). 표 머리 첫 칸에 쓴 글이 "Time Table" 자리에 들어간다. 일정 장은 C08 표보다 이것을 먼저 쓴다 |
| C13 | 운영조직 | 운영조직·투입 인력 (RFP 가 요구하면 필수) | `조직:` 들여쓰기 목록: `이름 \| 설명1; 설명2`. 더 깊게 들여쓴 줄이 바로 위 줄의 하위 조직. 옆으로 7열을 넘으면 말단 팀원은 부모 아래 세로로 쌓인다. POINT 막대는 두지 않는다 |
| L01~L06 | 회사 소개 | 고정 블록 | 회사 프로필 값으로 표, 또는 라이브러리 장표 (library.json) |

## 3-1. 표현 고르기: 표는 마지막 선택

장 유형을 정하기 전에 그 장이 보여 줄 내용부터 본다. `단계:` 와 `데이터:` 는 어느 C 유형에서도 그려진다.

| 보여 줄 내용 | 쓸 표현 | outline 필드 |
|---|---|---|
| 순서 · 공정 · 업무 흐름 · 생애주기 | 흐름도 | `단계:` (C04, C10 등) |
| 항목 간 크기 비교 · 전후 성과 | 막대 차트 | `데이터:` (C05, C09 등) |
| 월별 물량 · 시간에 따른 추이 | 선형 차트 | `데이터:` + `차트: 선형` |
| 전체 대비 비중 (6조각 이하, 계열 하나) | 원형 차트 | `데이터:` + `차트: 원형` |
| 운영조직 · 투입 인력 · 보고 체계 | 조직도 | C13 `조직:` |
| 일정 · 전환 계획 | 간트형 타임테이블 | C12 `기간:` + `일정:` |
| 1안/2안 · 대안 비교 | 2단 카드 | C07 `본문:` |
| 센터 · 설비 · 시스템 화면 · 현장 모습 | 사진 (1~4장) | `사진:` (`ref-search --photos` 로 레퍼런스에서 찾는다) |
| 요건별 대응 · 단가 · 증빙처럼 칸마다 정확히 대조할 값 | 표 | `표:` |

- 표만 있는 장은 본문 장의 절반을 넘기지 않고, 3장 이상 잇지 않는다. 섹션마다 흐름도·차트·타임테이블 중 하나를 둔다. `outline-check` 가 O17 로 경고한다.
- 표가 꼭 필요한 섹션은 앞에 그 내용을 요약한 흐름도나 차트 장을 먼저 둔다.
- 차트 숫자를 지어내지 않는다. 숫자가 없으면 `[확인 필요: 무엇을]` 로 남기고, 그럴듯한 예시 값으로 채우지 않는다.
- `차트:` 값이 틀리거나 원형에 맞지 않는 데이터면 O18, 조직도가 8열 5줄을 넘으면 O19 로 경고한다.
- 사진은 레퍼런스 색인에서 가져온다 (`ref-search "<주제>" --photos` → `ref-show` → Read 로 보고 고르기). 레퍼런스에 없는 사진(새 센터 등)만 제작 후 PowerPoint 에서 넣고, 그 필요를 사용자에게 알린다.
- `- 사진:` 항목은 `ref:<id>/<키> | 캡션` 또는 `<파일 경로> | 캡션`. 사진은 칸을 꽉 채우도록 넘치는 쪽을 자르고, 도면·화면 캡처처럼 잘리면 안 되는 것은 `| 캡션 | 맞춤` 으로 전체를 넣는다. 1장은 칸 전체, 2~3장은 나란히(칸이 세로로 길면 위아래), 4장은 2×2.

## 3-2. 한 장 구성: 블록 2~3개를 묶어 꽉 채운다 (기본)

본문 장은 블록(표 · 카드 `본문:` · 흐름도 `단계:` · 차트 `데이터:` · 조직도 `조직:` · 사진 `사진:`) **2~3개를 한 장에 묶는 것이 기본**이다.
한 블록만 크게 놓은 장은 비어 보인다. 결론을 보여 주는 블록(흐름도·차트)과 그것을 받치는 블록(기준 표·효과 카드)을 짝지어 넣는다.

| 배치 | 모양 | 자동으로 고르는 경우 |
|---|---|---|
| 좌우 | 블록을 옆으로 나란히 | 블록 2개 (넓은 블록이 없을 때) |
| 상하 | 위아래로 | 블록 2개 중 하나가 일정(C12)이거나 4단계 이상 흐름도일 때 |
| 좌1우2 | 왼쪽 큰 칸 1 · 오른쪽 위아래 2 | 블록 3개 (넓은 블록이 없을 때). 첫 블록이 왼쪽 |
| 상1하2 | 위 넓은 칸 1 · 아래 좌우 2 | 블록 3개 중 넓은 흐름도·일정이 있을 때 (그 블록이 위) |

- 블록은 outline 에 **쓴 순서대로** 왼쪽→오른쪽, 위→아래에 놓인다.
- `- 배치: 좌1우2 6:4` 처럼 모양과 비율을 직접 정할 수 있다. 비우면 위 표대로 자동.
- 블록 필드 뒤에 쓴 글은 블록 위 소제목이 된다: `- 표: 입고 기준` (아래 줄에 표). 묶음 장에서는 블록마다 소제목을 단다.
- 묶음 장의 블록은 칸을 끝까지 채운다. 칸이 좁으면 카드는 세로로 쌓이고 흐름도는 위→아래 흐름으로 바뀐다.
- 내용이 칸보다 길면 `render` 결과의 `tight` 에 그 장과 블록이 나온다. 글을 줄이거나 비율을 바꾼다.
- 한 장에 블록 4개 이상, 블록 하나뿐인 장이 본문의 절반 초과, 모르는 배치 값은 `outline-check` 가 O20 으로 경고한다. C01 · C07 · C12 · C13 은 전용 배치라 한 블록이어도 된다.

```
## 07 · C04
- 섹션: 02 운영 방안
- 제목: 입고 운영
- 메시지: 입고 당일 검수를 끝내 재고 반영을 하루 앞당기겠습니다.
- 단계: 입고 흐름
  - 도착 | 차량 예약; 도크 배정
  - 검수 | PDA 전수 검수
  - 적치 | 로케이션 지정
- 표: 입고 기준
  | 항목 | 기준 |
  |---|---|
  | 검수 시간 | 도착 후 4시간 이내 |
- 본문: 기대 효과
  - 재고 반영 D+1 → D+0
- 배치: 좌1우2 6:4
```

## 4. outline.md 문법

```markdown
# <덱 제목>
- 고객사: <고객사명>
- 건명: <건명>
- 날짜: 2026.01.31
- 제안사: <우리 회사 법인명>

## 01 · T01
- 메시지: <부제>

## 04 · C03
- 섹션: 03 운영 프로세스
- 제목: 입고 · 보관 운영 방안
- 메시지: <거버닝 메시지>
- 근거: R-WRT-03, R-SOW-01
- 본문:
  - 【 소제목 】
  - 불릿
- 표:
  | 요구 사항 | 우리 대응 | 근거 · 증빙 |
  |---|---|---|
  | … | … | … |
- 단계:
  - 입고 | PDA 전수 검수; 당일 완료
- 데이터:
  | 월 | 택배 | 우편 |
  | 1월 | 639 | 261 |
- 차트: 선형            (막대 · 선형 · 원형, 생략하면 막대)
- 배치: 좌1우2 6:4      (블록 2~3개 묶는 모양: 좌우 · 상하 · 좌1우2 · 상1하2, 생략하면 자동)
- 사진: 곤지암 센터
  - ref:ably-2603/s11-1 | 센터 전경
  - ref:ably-2603/s22-1 | 1층 레이아웃 | 맞춤
- 출처: ably-2603 11장   (가져온 레퍼런스 장 기록, 렌더하지 않음)
- 조직:
  - 총괄 PM | 계약; 보고
    - 운영팀 | 입출고; 재고
    - CS팀 | 클레임
- 상태: 초안
```

- 제목줄은 `## <번호> · <유형코드>`. 번호는 직접 고치지 말고 `outline-renumber` 로 다시 매긴다.
- 섹션은 `<번호> <이름>` (예: `03 운영 프로세스`). 같은 섹션은 같은 문자열로 쓴다 — 목차가 여기서 만들어진다.
- 한 슬라이드에 본문·표·단계·데이터를 2~3개 함께 쓰면 3-2절의 묶음 배치로 칸을 나눠 채운다. `- 표: 소제목` 처럼 필드 뒤에 글을 쓰면 블록 소제목이 된다.
- 모르는 값은 `[확인 필요: 무엇을]` 로 남긴다 (지어내지 않는다). 제작물에서 파란색으로 표시되고 점검에서 치명으로 잡힌다.

### C12 타임테이블 예

```
## 16 · C12
- 제목: 세부 추진 계획 (Milestone)
- 메시지: 계약 후 5주 안에 … 개시하겠습니다.
- 기간: 10월 4W, 11월 1W, 11월 2W, 11월 3W, 11월 4W, 12월 1W
- 일정:
  | Time Table (계약 10월 4주 가정) | 세부 일정 | 시작 | 끝 | 표시 |
  |---|---|---|---|---|
  | 계약 | 계약 체결 | 10월 4W | 10월 4W | 완료 |
  | 시스템 | SAP ↔ WMS 연동 | 11월 1W | 11월 4W | 완료 |
  | GO-LIVE | 통합 운영 개시 | 12월 1W | 12월 1W | 개시 |
```
