# 잘 만든 제안서에서 배운 장 패턴

사용자가 "잘 만든 덱"으로 지정한 gold 레퍼런스들의 장 그림을 보고 정리했다. 고객명과 수치는 빼고 방식만 남겼다.
각 레퍼런스의 장별 구성은 `ref-show <id> <장>` 결과의 `layout` 에서 보고, 덱 전체 분석은 `digest.md` 끝의 "구성 분석"에서 본다.
S5(구성)에서 장마다 아래 패턴 하나를 고른 뒤, 그 장을 outline 블록으로 옮긴다.

## 1. 덱 흐름 (페이지 구성)

1. **챕터 이름과 순서는 RFP를 따른다.** RFP 목차, 평가 항목, PT 주제를 그대로 챕터로 만든다. 평가자가 채점표를 들고 해당 장을 바로 찾을 수 있어야 한다.
2. **요약을 맨 앞에 둔다.** 핵심 요약, 특장점, 기대효과를 1~3장으로 쓴다. RFP가 요약서 쪽수를 정하면 그 쪽수를 지킨다.
3. **기본 줄거리**는 아래 순서다. RFP에 없는 챕터는 빼고, 있는 챕터는 이 순서 안에 끼운다.
   1. 요약
   2. 제안 개요: 배경·범위·특장점
   3. 회사 소개: 역량·네트워크·실적·유사 레퍼런스
   4. **고객 현황 분석(AS-IS)**: RFP 데이터 재분석 → Pain Point
   5. **운영 전략(TO-BE)**: 컨셉 → 시나리오 비교·시뮬레이션 → 제안 거점 → 레이아웃
   6. 프로세스: 입고·보관·출고·반품·재고
   7. 사업·채널별 특화 운영
   8. 피크 대응
   9. IT: 공통 → 채널별 연동
   10. 이관·구축: 일정·방법론·테스트·리스크
   11. 품질: SLA·KPI·조직·보안
   12. 물류비
   13. 기타: 제약·보험·위험물·계약 조건
4. **같은 숫자를 끝까지 이어 쓴다.** 분석 장에서 꺼낸 물동량·피크 배수·캐파를 진단 → 거점 → 프로세스 → 인력 산정 → 물류비 장까지 같은 값으로 쓴다.
5. **RFP 데이터를 다시 분석해 보여 준다.** RFP가 준 출고표를 그대로 옮기지 말고 비율, 증가율, 피크 월, 포장·규격 분포를 더해 첫 사업 장에 둔다.
6. **필수 항목 대응표를 먼저 만든다.** RFP의 "필수 포함 내용"을 한 줄씩 적고 담당 장을 정한다. 빠진 항목은 기타 장에라도 넣는다(놓치기 쉬운 예: 계약해지 조건, 사고보상 기준, 보험).
7. **약점은 스스로 밝히고 보완책을 붙인다.** 협업 구조나 상온 전용처럼 상대가 물을 약점은 "약점 → 보완" 카드 쌍으로 먼저 쓴다.
8. 간지는 섹션명 아래에 그 섹션의 장 제목들을 하위 항목으로 나열한다. 목차와 간지의 번호·이름은 같아야 한다(Q06).

## 3. 다이어그램 종류와 쓰는 곳

- **가로 흐름(쉐브론)**: 단계가 5개 안팎인 전체 프로세스. 아래에 단계별 설명 칸을 둔다.
- **세로 순서도(마름모 분기)**: 판단이 있는 공정(재고 확인, 검수 일치 여부). 분기마다 Y/N을 쓴다.
- **3단 흐름도(출발 → 거점 → 도착)**: 운송 구조. 선에 거리 칩을 단다.
- **AS-IS → TO-BE 상하 흐름도**: 제안 요약. 가운데에 큰 화살표를 둔다.
- **관계도(박스 + 양방향 화살표 + 관계 라벨)**: 고객 · 제안사 · 파트너 계약 구조.
- **조직도**: 운영 조직, 소방조, 개발 조직.
- **시스템 연동도**: 자사 시스템 표 ↔ 고객 시스템 표를 화살표로 잇는다. 3×2 격자로 여러 고객 사례를 둔다.
- **순환 다이어그램**: 비전과 선순환 구조.
- **S자 타임라인**: 분기별 성과 변화(행사 대응 이력).
- **도면 위 구역 색칠**: 보관·작업·입출고 구역, 동선 화살표, CCTV 범위 원.
- **간트**: 이관 일정, 하루 운영 시각표.

## 4. 이미지 활용

- **센터·설비 사진**: 사진 아래 주색 캡션 띠를 단다. 큰 사진 1장과 작은 사진 3장, 또는 3×2 격자로 둔다.
- **도면**: 센터 레이아웃 위에 구역을 반투명 색으로 칠하고 이름표를 단다. 작업 위치는 점선 박스로, 동선은 굵은 화살표로 그린다. 프로세스 장의 왼쪽 칸에 둔다.
- **지도**: 거점 핀과 센터 카드, 거리 표를 함께 쓴다.
- **시스템 화면 캡처**: PDA·WMS·대시보드 실제 화면에 주석 화살표를 단다. 고객 정보는 블러 처리한다.
- **고객 제품 사진**: 목차·간지 배경, 레퍼런스 열에 쓴다.
- **증빙 이미지**: 신용등급 확인서, 라벨 견본, 카톤 라벨.

## 5. 표 강조 규칙

- 머리 행은 회색이나 주색으로 채운다.
- 강조 행은 연한 노랑 음영, 핵심 열은 빨간 테두리, 결론 열(To-be·운영 가능)은 진한 주색으로 채운다.
- 증감은 + 빨강, − 파랑으로 쓰고, 피크 월은 열 테두리로 표시한다.
- 표 아래에는 각주(※ 기준·출처)를 단다.

## 6. 제출 직전 다듬기 (최종본에서 실제로 고친 것)

- 그래프의 마지막(예상) 막대 위에 "전년비 +N%"를 단다. 숫자를 읽지 않아도 성장이 보이게 한다.
- 사례 여러 개를 나란히 둘 때는 고객과 가장 가까운 사례(같은 그룹사, 같은 업종)를 첫 열에 둔다. 성장 배수 말풍선("+N%, N배 성장")을 붙인다.
- 실적 수치는 제출 시점의 가장 최근 값으로 바꾼다(작년 행사 → 올해 행사).
- 일정이나 수치를 하나 바꾸면 같은 값이 나오는 모든 장을 함께 고친다(인수인계 장 ↔ 제약 조건 장의 개시일).
- 마지막 장은 표지와 같은 틀로 "감사합니다 + 건명 | 제안사"를 둔다.

## 7. 렌더러로 안 되는 것

순환 다이어그램, 도면 위 색칠, 지도 핀, S자 타임라인, 2×2 네 블록 배치는 아직 렌더러가 그리지 못한다.
- 레퍼런스에 같은 그림이 있으면 `사진: ref:<id>/<키> | 캡션 | 맞춤` 으로 가져온다.
- 없으면 outline 에 `[확인 필요: 도면 — 구역 색칠]` 처럼 남기고, 제작 후 수작업할 목록에 올린다.
