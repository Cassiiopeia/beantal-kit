# bean-skill-manager

사용자는 하던 작업을 계속하고, 레포 작업은 뒤에서 처리한다. 사용자는 개발자가 아닐 수 있으므로 레포, 이슈, 커밋, 배포 같은 말을 먼저 꺼내지 않는다.

## 언제 쓰는가 / 쓰지 않는가

- 쓴다: `bean-*` skill 결과에 대한 지속적인 불만이나 요구, 반복될 새 작업, 자동 수리 설정
- 쓰지 않는다: 이번 문서의 오타·내용 수정처럼 현재 작업에서 끝나는 요청, 빈털킷과 무관한 일반 코딩 요청

## 시작할 때

스크립트는 이 SKILL.md 가 있는 폴더의 `scripts/skill_manager_cli.mjs` 다. 아래에서 `$CLI` 는 그 경로를 뜻한다.

```bash
node "$CLI" status
```

Node.js 20.12 이상이 필요하다. 확인: `node --version`. 없으면 nodejs.org 설치를 안내한다.

| code | 뜻 | 할 일 |
|---|---|---|
| `not_configured` | 이 PC는 자동 수리가 꺼져 있음 | 사용자가 설정을 요청했으면 아래 "설정", 아니면 1·2단계만 처리 |
| `not_installed` | 플러그인 설치 기록 없음 | `npx beantal-kit` 안내 |
| `ready` | 사용 가능 | 분류 진행 |

## 요구 분류

요구마다 먼저 현재 작업에 반영한 뒤 단계를 판단한다. 애매하면 낮은 단계로 둔다 (이유: 3단계 이상은 모든 사용자에게 배포된다).

| 단계 | 기준 | 처리 |
|---|---|---|
| 1. 이번 작업 한정 | 이 문서의 내용, 이 고객사의 사실 | 현재 작업에서 끝 |
| 2. 개인 취향 | 다음에도 원하지만 사람·회사마다 다름 | 해당 skill 의 설정 칸에 저장. 칸이 없으면 `~/.beantal-kit/configs/<skill폴더명>/preferences.md` 에 한 줄 추가 |
| 3. 공통 개선 | 어떤 사용자에게도 맞는 동작, skill 의 버그 | 뒷단으로 넘겨 기존 skill 수정 (묻지 않음) |
| 4. 새 기능 | 앞으로 자주 쓸 작업인데 맡을 skill 이 없음 | 한 번 물은 뒤 뒷단으로 넘겨 새 skill 생성 |

3·4단계는 아래를 모두 만족해야 한다.

- 고객사, 건명, 특정 수치 없이 규칙 한 문장으로 일반화할 수 있다.
- 다른 사용자의 결과를 나쁘게 만들지 않는다. 취향이 갈리면 기본값을 유지하고 옵션을 추가한다.

4단계는 아래도 만족해야 한다.

- 기존 skill 범위에 들어가지 않는다. 들어가면 3단계로 처리한다.
- 반복될 근거가 있다. 사용자가 "매번", "앞으로"라고 말했거나 같은 요구가 대기열 기록에 있다.

4단계 질문은 쉬운 말로 한 번만 한다.

> 이 작업은 자주 쓰실 것 같은데, 빈털킷 기능으로 만들어서 올려둘까요?

거절하면 현재 대화에서만 처리하고, `~/.beantal-kit/configs/bean-skill-manager/declined.md` 에 일반화한 요구를 한 줄 적어 같은 제안을 반복하지 않는다.

## 뒷단으로 넘기기

백그라운드 에이전트를 띄우고 곧바로 사용자의 작업으로 돌아온다. 같은 요구를 중복으로 넘기지 않는다. 에이전트에게 주는 내용은 아래뿐이다.

- 읽을 문서: 이 폴더의 `references/background-procedure.md`
- 단계(3 또는 4), 대상 skill 이름(4단계는 제안 이름)
- 일반화한 요구 한 문장과 재현 조건 (고객사명, 파일명, 문서 본문 제외)
- 이 skill 폴더의 경로

결과를 받으면 사용자에게 한 줄로만 전한다. 실패해도 하던 작업을 막지 않는다.

- 배포 완료: "다음 작업부터 이렇게 나오도록 고쳐뒀어요."
- PC 반영 후 공용 반영 대기: "이 PC에는 적용했고, 다른 분들께는 다음 업데이트 때 전달돼요."
- 실패: "이번 개선은 적용하지 못했어요. 지금 작업은 그대로 진행할게요."

PC 반영은 새 대화부터 적용되므로, 현재 대화에서는 앞단이 직접 요구대로 작업한다.

## 설정

- 설정 파일 위치는 고정이다: `~/.beantal-kit/configs/bean-skill-manager/config.json` (Windows: `%USERPROFILE%\.beantal-kit\configs\bean-skill-manager\config.json`). 탐색하지 말고 이 경로를 바로 읽는다.
- 템플릿은 이 skill 폴더의 `config.json.example` 이다. 각 칸의 의미는 `_comment_*` 에 적혀 있다.
- **플러그인 폴더(캐시) 안에는 설정을 절대 쓰지 않는다.** 플러그인을 업데이트하면 폴더가 바뀌어 설정이 사라진 것처럼 보인다.
- 사용자가 파일을 직접 편집하게 하지 않는다. 기존 값은 덮어쓰지 않고 빠진 키만 보충한다.

자동 수리를 켜는 대화는 한 번에 한 질문씩 진행한다.

1. **레포 위치**: clone 한 `beantal-kit` 폴더를 찾아 확인한다. `git -C "<폴더>" remote get-url origin` 에 `beantal-kit` 이 있어야 한다.
2. **자동 사용 동의**: "요청하신 개선을 다른 사용자에게도 자동으로 배포하게 됩니다"라고 설명하고 동의를 받는다. 동의하면 `repo_path`, `enabled: true`, `maintainer_github` 를 저장한다.
3. **자동 승인**: `pro-commit`, `pro-github`(이슈 생성), `pro-changelog-deploy` 의 자동 진행 설정을 **이 레포에만** 켠다. 각 skill 에 "이 레포는 자동으로 진행해줘"라고 요청하고, projectops 설정 파일은 직접 읽지 않는다 (이유: 토큰이 대화 기록에 남는다).
4. **확인**: `status` 가 `ready` 이고 `hasRepository`, `hasProjectops` 가 true 인지 본다.

뒷단이 권한 확인 창에 막히면, 사용자 동의를 받아 막힌 명령만 Claude Code 사용자 설정의 허용 목록에 추가한다.

## 개인 취향

시작할 때 `~/.beantal-kit/configs/bean-skill-manager/preferences.md` 가 있으면 읽어 따른다.

## 흔한 실수

- 고객사 이름이 든 요구를 그대로 뒷단에 넘긴다. 일반화한 문장만 넘긴다.
- 이번 문서만의 요구를 skill 에 넣는다. 단계를 낮춘다.
- 뒷단 진행 상황을 사용자에게 계속 보고한다. 결과 한 줄만 전한다.

## OS 호환 (macOS, Windows)

- 홈 폴더는 `~`, `$HOME`, `%USERPROFILE%` 로만 표기한다. 드라이브 문자나 사용자 이름이 들어간 절대 경로는 쓰지 않는다 (`npm run check` 가 막는다).
- 파일 읽기, 쓰기, 수정은 가능하면 agent 도구(Read, Write, Edit)로 한다. 셸 명령은 macOS 와 Windows 에서 똑같이 동작하는 것만 쓴다.
- 파일은 UTF-8, 줄바꿈은 LF 로 저장한다. 한글 파일명이나 공백이 든 경로는 따옴표로 감싼다.
