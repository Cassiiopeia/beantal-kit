# skill 제작 표준

projectops `pro-skill-creator` 의 기준을 사람에게 묻지 않는 뒷단용으로 옮긴 문서다. 뒷단은 질문할 수 없으므로, 대화에서 추출할 수 없는 정보가 있으면 추측하지 않고 보류한다.

| 모드 | 언제 | 절차 |
|---|---|---|
| CREATE | 4단계 새 skill | 슬롯 추출, 작성, 8원칙 점검, 트리거 점검, 이식성 점검 |
| IMPROVE | 3단계 기존 skill 수정 | 대상 수정, 8원칙 점검. 트리거가 바뀌면 트리거 점검 |

## 1. 슬롯 추출 (CREATE)

| 슬롯 | 내용 | 비어도 되는가 |
|---|---|---|
| `purpose` | 한 줄 목적 | 안 됨 |
| `triggers` | 어떤 말에 호출되는가 | 안 됨 |
| `outputs` | 결과 형태 | 안 됨 |
| `inputs` | 사용자가 줄 정보 | 됨 |
| `auto_extract` | 자료에서 자동으로 뽑을 값 | 됨 |
| `pain_points` | 손으로 할 때 불편했던 점 | 됨 |

필수 슬롯을 채울 수 없으면 만들지 않고 `abandoned` 로 끝낸다.

## 2. 작성

- 뼈대는 `npm run new-skill <이름>` 으로 만든다. 사람·PC마다 다른 값이 하나라도 있으면 `npm run new-skill <이름> -- --config` 를 쓴다.
- 폴더명 = frontmatter `name` = `bean-` 접두사. 이름은 하는 일이 드러나게 짓는다.
- 본문은 한국어. 구성: 언제 쓰는가·쓰지 않는가, 설정, 절차(정보 수집, 실행, 검증·보고), 흔한 실수.
- 분량에 맞게 쓴다. 500줄을 넘으면 `references/` 로 나눈다. 반복 작업은 `scripts/` 로 뺀다.
- "하지 말 것"에는 이유를 한 줄 붙인다.
- 외부 실행 환경이 필요하면 필요 조건, 확인 명령, 없을 때의 안내를 적는다.
- 결과물을 만드는 skill 이면 `skills/<skill>/references/verify.md` 에 가상 샘플 검증 절차와 통과 기준을 함께 쓴다. 고객 자료를 샘플로 쓰지 않는다.

## 3. 설정 분리 (확장성의 핵심)

- 사람, PC, 회사마다 다를 수 있는 값은 전부 `config.json` 으로 뺀다. 경로, 계정, URL, 회사명, 양식, 기본 형식, 언어가 해당한다.
- 설정은 `~/.beantal-kit/configs/<skill폴더명>/config.json` 에만 저장하고, 레포에는 `config.json.example` 만 둔다.
- example: 최상위 키는 skill 이름에서 `bean-` 을 뺀 이름, 값은 비움, `_comment_*` 로 설명, 필수 칸은 `_required`.
- 값 결정 순서: 요청에서 직접 준 값, 환경변수, config.json, example 기본값, (필수인데 없으면) 질문.
- 설정은 Claude 가 대화로 만든다. 한 번에 한 질문, 기존 값 유지, 토큰은 마스킹.
- 실제 도메인, IP, 이메일, 회사명을 SKILL.md 에 쓰지 않는다. `{자리표시자}` 를 쓴다.

## 4. 8원칙 점검

작성한 파일을 **다시 읽고** 항목별로 판정한다. 위반이 0건이 될 때까지 고친다.

| # | 원칙 | 통과 조건 |
|---|---|---|
| 1 | 한 번에 한 질문 | 한 메시지에 질문 2개 이상을 지시하지 않는다 |
| 2 | 자동 추론 우선 | 자료에서 알 수 있는 값을 다시 묻지 않는다 |
| 3 | 전문용어 설명 | 약어·고유명사를 처음 쓸 때 한 줄로 풀어 준다 |
| 4 | 구체적 UI 경로 | 화면 안내는 메뉴, 탭, 항목 이름까지 적는다 |
| 5 | 하드코딩 금지 | 실제 도메인, IP, 이메일, 회사명이 없다 |
| 6 | 설정 분리 | 사람마다 다른 값이 config 에 있다 |
| 7 | 실제 경험 반영 | 확인하지 않은 경고는 빼거나 `(미확인)` 표시한다 |
| 8 | 유연한 입력 | 정보를 한 번에 줘도 받아들인다 |

## 5. 트리거 점검

`description` 만 보고 판정한다. 5/5 통과까지 고친다.

- 호출되어야 할 말 3개: skill 이름을 말하지 않는 실제 말투
- 호출되면 안 될 말 2개: 가까운 주제
- 기존 `bean-*` skill 과 트리거가 겹치면 범위를 좁힌다.

## 6. 이식성 점검

설정이 없는 다른 PC에서 받았다고 가정한다. 대화로 설정을 만든 뒤 동작할 수 있어야 한다. 아래 중 하나라도 있으면 불통과다.

- 특정 PC의 폴더 구조, 파일명, 설치 앱을 전제함
- macOS 나 Windows 한쪽에서만 동작함
- 설치 안내 없이 외부 프로그램을 요구함

## 7. 실제 호출 확인

배포 전에 `SKILL.md` 절차대로 가상 입력으로 실제로 한 번 실행한다. 절차와 통과 기준은 `background-procedure.md` 6단계를 따른다. 트리거 호출 여부는 첫 실사용에서 확인되며, 문제가 나오면 3단계 수리로 처리한다.
