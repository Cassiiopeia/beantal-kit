# bean-issue-first

새 작업은 이슈로 시작하고, 완료 증거를 이슈에 남기고 끝낸다.

## 언제 쓰는가

- 사용자가 새 기능, 수정, 검증 작업을 시키면서 "이슈화", "이슈 먼저", "작업 진행"을 말할 때
- 작업이 끝나 이슈를 완료 처리해야 할 때

## 절차

1. **이슈 초안**: 현재 문제점, 해결 방안, 작업 내용을 담은 초안을 로컬 md 파일로 저장하고 사용자에게 보여준다. 승인 전에는 등록하지 않는다.
2. **등록**: 승인되면 GitHub 이슈로 등록하고 이슈 번호와 URL을 사용자에게 알린다.
3. **작업**: 커밋 메시지는 `이슈제목 : feat|fix|docs|... : 설명 이슈URL` 형식을 따른다. 커밋 컨벤션이 정해지지 않았으면 먼저 묻는다.
4. **검증**: 테스트, 빌드, 실제 동작 확인 결과를 실행한 명령과 함께 모은다. 확인하지 못한 항목은 확인하지 못했다고 적는다.
5. **인증 댓글**: 구현 내용, 검증 증거 표, 남은 사항을 이슈 댓글로 남긴다.
6. **완료 처리**: 사용자가 요청한 경우 `작업완료` 라벨을 붙이고 이슈를 닫는다.

## 하지 않는 것

- 승인 없이 이슈를 등록하지 않는다.
- 검증하지 않은 내용을 완료로 적지 않는다.
- 커밋 메시지와 이슈 본문에 AI 작성 흔적을 남기지 않는다.
